# Behavior compatibility and source boundary

<p align="center">
  <strong>English</strong> | <a href="BehaviorCompatibility.ko.md">한국어</a>
</p>

SlugcatInMyMonitor aims to reproduce the *observable behavior* of Rain World's
Slugcats in a standalone Windows desktop environment without shipping the game,
its binaries, or its assets.

This document defines what belongs in the public repository when compatibility
work is performed.

## Public compatibility notes should contain

- User-visible behavior and expected outcomes.
- High-level movement, rendering, AI, and ability requirements.
- Regression scenarios that can be replayed in this project.
- Architecture decisions specific to the desktop implementation.
- Rules for locating and reading assets from a user's own Rain World installation
  without copying those assets into this repository or release packages.
- Measurements or tuning expressed as project test expectations rather than as a
  transcription of a third-party method body.

## Public compatibility notes should not contain

- Decompiled source code or reconstructed third-party method bodies.
- IL/ILDASM output, method tokens, RVAs, local binary offsets, or decompiler dumps.
- Proprietary DLLs, executables, extracted texture/audio payloads, or other game files.
- Detailed local-machine paths, hashes, or extraction logs that are useful only for
  reproducing a private reverse-engineering session.
- Copied comments or source-shaped pseudocode that preserves the expression of a
  third-party implementation.

## Implementation workflow

1. Describe the behavior that the desktop pet needs to reproduce.
2. Convert research into a small behavior-level specification or regression test.
3. Implement that specification using this project's own architecture and types.
4. Review the resulting code without relying on decompiler output in the PR.
5. Keep game binaries, extraction output, and private research notes outside git.

The desktop application may read compatible assets from a user's local Rain World
installation at runtime. Those assets remain external inputs and are not part of
this repository or its license.

## Current architectural compatibility goals

The public implementation is organized around a fixed-step simulation, connected
body parts, virtual input generated by the desktop AI, procedural pose generation,
desktop-window collision, and rendering from locally discovered atlas data. These
are behavioral/architectural goals of this project; this document intentionally
avoids source-level descriptions of Rain World's implementation.

This policy is repository hygiene guidance, not a legal opinion or a declaration
that any particular code is or is not infringing.
